## Code of Conduct

This project and everyone participating in it is governed by the [Code of Conduct](CODE_OF_CONDUCT.md). By participating, you are expected to uphold this code. Please report unacceptable behavior to the project maintainers.

## How Can I Contribute?

### Reporting Bugs

If you find a bug in the guide or a technical error, please help us by [opening an issue](https://github.com/tc4dy/support-tor-for-freedom/issues). Before creating a bug report, please check the existing issues to avoid duplicates.

**A good bug report includes:**
- **Quick summary:** A clear and concise description of the issue.
- **Steps to reproduce:** The exact steps to reproduce the problem.
- **Expected behavior:** What you expected to happen.
- **Actual behavior:** What actually happened.
- **Screenshots or logs:** If applicable, add screenshots or relevant log output to help explain your problem.
- **Environment:** (e.g., OS, Tor version, Raspberry Pi model).

### Suggesting Enhancements

We welcome ideas for new sections, better explanations, or additional resources. To suggest an enhancement, please [open an issue](https://github.com/tc4dy/support-tor-for-freedom/issues) and describe your suggestion in detail.

**A good enhancement suggestion includes:**
- **Clear title:** A descriptive title for the suggestion.
- **Detailed description:** What you want to be added and why it would be valuable.
- **Examples:** If applicable, provide examples of what you mean.

### Translations

One of the best ways to contribute is to make this guide accessible to more people by translating it. If you are fluent in another language and want to translate the `README.md`, please:

1.  Open an issue stating which language you are translating to.
2.  Submit a Pull Request with your translated version (e.g., `README.fr.md` for French).
3.  We'll review it and, once merged, link to it from the main README.

### Improving Documentation

Even small fixes like correcting typos, improving grammar, or clarifying a sentence are incredibly helpful. Please feel free to submit a Pull Request for any improvements you see.

## Your First Contribution

Unsure where to begin contributing? Here are some good first steps:

1.  **Star the repository** ⭐ to show your support.
2.  **Read through the README** and try to follow the guides. If something is unclear or you get stuck, that's a great thing to report!
3.  Look for issues labeled `good-first-issue` or `help-wanted`.

## Pull Request Process

We follow a standard GitHub fork and pull request workflow.

1.  **Fork the repository:** Create your own copy of the project.
2.  **Create a branch:** Create a branch for your change (e.g., `git checkout -b fix/typo-readme`).
3.  **Make your changes:** Add your improvements, fixes, or translations.
4.  **Test your changes:** Ensure the Markdown renders correctly on GitHub.
5.  **Commit your changes:** Use clear and descriptive commit messages. For example, `docs: fix typo in VPS setup section`.
6.  **Push to your fork:** Push your branch to your fork on GitHub.
7.  **Open a Pull Request:** Open a pull request from your fork to the `main` branch of `tc4dy/support-tor-for-freedom`. Provide a clear title and description explaining your changes and motivation.

## Style Guidelines

To keep the guide consistent and easy to read:

- **Markdown:** Use standard Markdown syntax.
- **Headings:** Use a consistent heading structure (`#`, `##`, `###`). Use sentence case for headings (e.g., "## Raspberry Pi Setup").
- **Language:** Use clear, simple, and inclusive language. The guide is for a global, beginner-friendly audience.
- **Code Blocks:** Use fenced code blocks (```` ``` ````) with appropriate language identifiers (e.g., `bash`, `torrc`) for configuration and commands.
- **Links:** Use descriptive link text (e.g., `[Tor Project Official Website](https://torproject.org)`).
- **Emojis:** Emojis are welcome to make the guide more engaging, but use them sparingly and appropriately.
